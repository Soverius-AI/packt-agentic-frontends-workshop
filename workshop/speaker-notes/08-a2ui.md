# 08 — Compose a result from Table, Card and Text

**Start:** completed 07. A working key and recent demo readings are required.
**Completed code:** [solution 08](../solutions/08/).

**Demo inputs:** Follow milestone 08 in the [demo prompt sequence](../demo-prompts.md)
or this chapter’s Demo prompts in the Presenter desk. Use the three core examples
in order; each replaces the previous generated view. The manager-card example
requires rehearsal: this worktree’s two live attempts rendered valid but incorrect
arrangements. Table-only and stored room-description examples passed.

## Say

“Until now, the application chose the result layout. We will give the agent three
components and let it arrange them. SQL still selects real data. The model chooses
the layout and bindings; the application supplies every table value.”

## Demonstrate

1. Send the table-only prompt from Demo prompts. Confirm exactly the requested
   Time, Temperature and Shift Manager columns. Page the table. There should be
   no surrounding titled Card, explanatory Text, or manual column chooser.
2. Rehearse the manager-card prompt first. If the output combines rooms or puts
   manager names on Tables instead of Cards, use it to review the unmet request.
   A passing result has manager Cards containing a short layout
   introduction and separate room Tables. Inspect one table’s manager/room scope.
   Page one table and verify the others keep their positions. Model-written
   introductions describe the layout; they must not interpret unseen temperatures.
3. Send the room-overview prompt. Show that two Cards containing stored descriptions
   replace the temperature tables. Follow the native binding to the actual room
   description. This proves the catalogue composes different kinds of views.
4. Optionally request an average-temperature table per manager. Contrast this with
   the rejected aggregate in 06. Inspect the SQL/dataset and calculated result;
   do not treat a confident chat acknowledgement as numerical evidence.
5. In Studio inspect the format and composition steps. In the transported result
   show `createSurface`, `updateComponents`, and `updateDataModel`. Explain the
   current-result receipt, browser-history filtering and `ToolCallFilter` together.
